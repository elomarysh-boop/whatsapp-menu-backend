# WhatsApp Multi-Tenant Menu Backend

Backend Node.js/JavaScript لبوت قائمة WhatsApp متعدد المتاجر باستخدام Baileys وSupabase.

## ما يطبقه المشروع

- جلسة WhatsApp مستقلة لكل متجر، وملف مصادقة منفصل داخل `.wa-auth/<store-id>`.
- رسائل صادرة inbound-only: لا يوجد أي مسار للإرسال إلا داخل معالج رسالة واردة أو نتيجة طلب وارد.
- طابور إرسال لكل متجر مع تأخير عشوائي بين 1.5 و3.5 ثانية بين الرسائل.
- جلسة عميل مؤقتة في الذاكرة تتضمن الحالة والسلة وتنفصل بمفتاح `storeId:phone`.
- قوالب الرسائل تقرأ الأقسام والمنتجات والأسعار مباشرة من Supabase.
- إنشاء الطلب النهائي في `orders` بحالة `pending`.
- تجاهل المجموعات والرسائل الصادرة من الحساب نفسه.

> التأخير والعزل يقللان المخاطر التشغيلية، لكن لا يمكن لأي مكتبة أن تضمن عدم حظر رقم WhatsApp. استخدم الحسابات والموافقة والرسائل المتوقعة من العملاء، والتزم بسياسات WhatsApp.

## التشغيل

```bash
cp .env.example .env
# عدّل SUPABASE_URL وSUPABASE_SERVICE_ROLE_KEY
npm install
npx supabase db push
npm start
```

شغّل `npm run dev` للتطوير. افتح `GET /health` للتحقق من اتصال Supabase.

## إضافة متجر

أدخل سجلاً في `stores` مع رقم WhatsApp بصيغة رقمية، ثم أضف `categories` و`products` مع `store_id`. عند بدء الخادم سيقرأ المتاجر النشطة وينشئ اتصالاً مستقلاً لكل واحد منها. سيظهر QR في الطرفية لكل جلسة غير موثقة.

## ملاحظات إنتاجية

- لا تضع `SUPABASE_SERVICE_ROLE_KEY` في الواجهة أو مستودع Git.
- في بيئة متعددة النسخ، انقل `SessionStore` و`OutboundQueue` إلى Redis مع قفل/توزيع، أو شغّل نسخة واحدة لكل متجر؛ النسخة الحالية مصممة لعزل داخل عملية Node واحدة.
- استخدم تخزيناً دائماً لمجلدات `.wa-auth`، ونسخاً احتياطية آمنة، ومراقبة للاتصالات.
- لإضافة لوحة تحكم، أنشئ سياسات RLS منفصلة للمستخدمين الإداريين ولا تعرّض مفتاح الخدمة.
